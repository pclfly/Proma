# Proma Open API 接入

仅当成品需要在 Proma Agent 不在场时独立调用模型或多模态能力时使用本页。具体协议参数按需读取 `proma-cloud-sdk` references。

## 密钥边界

1. 不复用 Agent 的内置凭据；它只供 Agent 构建过程使用。
2. 独立应用需要凭据时，请用户在 Proma 设置中创建专用、额度受限的 key。
3. 私有、本地、不可分享的原型可将 key 写入本地 `.env`；如果确实写入静态 HTML，必须醒目标明文件含密钥、不能分享或提交。
4. 公开站点、多人产品、可下载客户端、仓库代码和任何前端 bundle 都不能包含真实 key。使用服务端环境变量或用户自带鉴权。
5. `.env.example` 只能写占位符，`.gitignore` 必须忽略 `.env`；交付时报告 key 名、额度和设置中的管理位置，不在文档复制 key。

## 实时模型发现

不要使用静态模型名、固定价格或按模型名称猜协议。构建阶段执行：

1. 请求用户提供可用的 Proma API Key 与 `baseUrl`；不要尝试读取 Agent 的内部凭据。
2. 归一化根地址：剥去可选的 `/api/v1` 后缀。
3. 请求 `GET {root}/v1/models` 获取当前模型目录。
4. 若要判断计费、输入能力或协议兼容性，再请求 `GET {root}/api/v1/models`。
5. 结合目标任务和返回元数据选择模型、端点与请求格式；把选择理由和运行期限制写入交付说明。

如模型目录无法获取，要求用户恢复登录或网络后再继续；不要退回到本 Skill 中不存在的“默认模型”。

## 协议选择

以实时目录和协议元数据为准：

- 只有明确支持 Messages 的模型才使用 `/v1/messages`。
- 支持 Chat Completions 的模型使用 `/v1/chat/completions`。
- 需要 Responses 语义的模型使用 `/v1/responses`，请求体遵循该接口。
- 向量和图像等能力使用其对应的已发布端点与实时可用模型。

不要让单个前端下拉框假设所有目录模型都兼容同一端点。

## 创建 app key 后的交付

说明应用路径、运行方式、key 名、额度、Proma 设置中的管理入口，以及泄露或不再使用时的禁用/删除方式。若创建失败是 app key 数量上限，停止重试，请用户先在设置中清理不再使用的 key。
